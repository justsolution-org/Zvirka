## Що робить додаток

Приватний виконавець або бухгалтер завантажує два Excel-файли:

1. **Реєстр ВП** — експорт з АСВП (Автоматизованої системи виконавчого провадження) з переліком виконавчих проваджень
2. **Книга депозитних сум** — бухгалтерський звіт надходжень на депозитний рахунок виконавця за конкретний місяць

Додаток зіставляє їх за **номером виконавчого провадження** і формує зведений Excel-файл з інформацією про кожне ВП та суми надходжень.

Вся обробка відбувається **в браузері** — жодні дані не передаються на сервер.

## Предметна область

### Глосарій

| Термін | Пояснення |
|---|---|
| **ВП** | Виконавче провадження — справа про примусове стягнення боргу |
| **АСВП** | Автоматизована система виконавчого провадження — державний реєстр, звідки експортується файл ВП |
| **№ АСВП** | Унікальний номер провадження в системі АСВП (7–8 цифр, напр. `63742507`) |
| **№ ВД** | Номер виконавчого документа (підстава для відкриття ВП) |
| **Боржник** | Особа, з якої стягується борг |
| **Стягувач** | Особа або організація, на користь якої стягується борг |
| **Депозитний рахунок** | Спеціальний банківський рахунок виконавця, куди надходять стягнуті кошти |
| **Книга депозитних сум** | Обліковий документ руху коштів на депозитному рахунку (додаток 4 до Інструкції) |

### Бізнес-контекст

Приватний виконавець щомісяця повинен звіряти: які кошти фактично надійшли на депозитний рахунок і до яких проваджень вони належать. Ця ручна робота забирає години — додаток автоматизує її до секунд.

## Вхідні файли — формат і структура

### Файл 1: Реєстр ВП (експорт з АСВП)

**Типова назва**: `ВП_2026_03_16__16_18_52.xlsx`

**Структура** (SheetJS бачить з обрізаною колонкою A — див. [Lessons Learned](#критичні-технічні-рішення-lessons-learned)):

| Реальна колонка Excel | Заголовок | Використовується | Поле |
|---|---|---|---|
| B | У складі ЗВП № | **Так (групування зведених)** | `zvp` |
| **C** | **№ АСВП** | **Так (ключ зв'язку)** | `vpNum` |
| D | № ВД | Так | `vd` |
| E | Дата надходження | Ні | — |
| F | Вхідний № ВД | Ні | — |
| G | Стан ВП | Так | `stanVP` |
| H | Стан ВД | Так | `stanVD` |
| I | Назва | Ні | — |
| J | Дата видачі | Ні | — |
| K | Дата відкриття ВП | Так | `dateOpen` |
| L | Сума коштів до стягнення, грн. | Так | `amount` |
| M–U | (інші поля) | Ні | — |
| V | Боржник | Так | `debtor` |
| W | Стягувач | Так | `creditor` |

**Особливості**:
- Рядок 1 — назва файлу (заголовок), не дані
- Рядок 2 — назви колонок
- Рядки 3+ — дані
- Колонка A часто порожня → SheetJS обрізає її → **всі індекси зсуваються на 1 вліво**

### Файл 2: Книга депозитних сум

**Типова назва**: `DepositBook.xlsx` або `DepositBook (15).xlsx`

**Структура**: два аркуші — `Page1` (титульна сторінка) і `Page2` (дані).

**Аркуш Page2** (SheetJS-індекси):

| Реальна колонка Excel | Заголовок (рядок 2) | Використовується |
|---|---|---|
| B | № з/п | Ні |
| **C** | **Номер виконавчого провадження** | **Так (ключ зв'язку)** |
| D | Виконавець | Ні |
| **E** | **Дата зарахування коштів** | **Так** |
| F | Повне найменування платника | Ні |
| G | Назва платежу | Ні |
| H | (merged) | — |
| I | Залишок коштів на початок місяця | Ні (fallback) |
| **J** | **Сума, що надійшла в поточному місяці** | **Так** |

**Особливості**:
- Рядки 1–4: заголовки та під-заголовки (merged cells)
- Рядок 5 або 6: перший рядок даних
- Наявність рядка "Розшифровка залишку коштів..." — його треба пропустити
- Не всі рядки мають номер ВП (деякі — невизначені платежі)
- Дві колонки сум:
  - **I** — залишок з попередніх місяців (НЕ використовується)
  - **J** — надійшло в поточному місяці (використовується)
- Записи з J = 0 пропускаються — означає, що надходження не було в цьому місяці

## Алгоритм обробки

### Stage 1: Зчитування файлів
```
FileReader.readAsArrayBuffer → ArrayBuffer
```
Валідація: розширення (.xlsx/.xls), розмір (< 50 MB).

### Stage 2: Парсинг реєстру ВП

```
1. XLSX.read(buffer) → workbook
2. sheet_to_json(sheet, { header: 1 }) → масив масивів
3. Пошук рядка заголовків: сканувати рядки 0–4, знайти той, де є "АСВП"
4. findColIndex для кожної потрібної колонки (за фрагментом назви)
5. Ітерація рядків від headerRow+1: витягти записи з валідним vpNum (/^\d+$/)
```

**Результат**: масив `VPRecord[]`

### Stage 3: Парсинг книги депозитних сум

```
1. XLSX.read(buffer) → workbook
2. Знайти аркуш: спочатку "Page2", потім пошук по "виконавчого провадження"
3. sheet_to_json → масив масивів
4. Пошук рядка заголовків: "виконавчого провадження" в рядках 0–9
5. findColIndex для: vpNum, date, sumJ, sumI
6. Визначення першого рядка даних (пропустити під-заголовки)
7. Ітерація: витягти записи, ПРОПУСТИТИ де sum = 0
```

**Результат**: `Map<vpNum, DepositEntry[]>`

### Stage 4: Зіставлення

```
for кожне ВП:
  якщо є надходження → записати (окремо або сумувати)
  якщо немає надходження і toggle "Усі ВП" ON → записати з нулями
  якщо немає надходження і toggle "Усі ВП" OFF → пропустити
```

### Stage 5: Генерація XLSX

```
1. Сформувати заголовки (залежать від режиму сумування)
2. XLSX.utils.aoa_to_sheet([headers, ...rows])
3. Задати ширини колонок
4. XLSX.writeFile → скачування
```

## Режими роботи (тогли)

### Toggle 1: Усі ВП з реєстру

| Стан | Поведінка |
|---|---|
| **ON** (default) | Всі ВП з реєстру потрапляють у звіт. Без надходжень — стоїть 0. |
| **OFF** | Тільки ВП, по яких є ненульові надходження в депозитних книгах. |

### Toggle 2: Розгортати зведені (ЗВП)

Керує тим, як показувати зведені виконавчі провадження (див. розділ про ЗВП).

| Стан | Поведінка |
|---|---|
| **OFF** (default) | Кожне ЗВП — **один** рядок (`Тип = ЗВП`). Сума = надходження на номер ЗВП + надходження на всіх членів. Окремих рядків членів немає. |
| **ON** | Якщо гроші надходили прямо на номер ЗВП — рядок `Тип = ЗВП (пряме)`. Плюс окремі рядки членів (`Тип = член ЗВП`); чи виводити членів без надходжень — керує Toggle 3. |

### Toggle 3: Показувати нульових членів ЗВП

Діє **лише** коли Toggle 2 увімкнено (інакше неактивний — членів узагалі немає). На реальних даних членів ЗВП без власних надходжень — переважна більшість (1269 із 1286), бо кошти зведеного приходять на номер ЗВП, а не на членів.

| Стан | Поведінка (у розгорнутому режимі) |
|---|---|
| **ON** (default) | Виводяться всі члени ЗВП, зокрема з нульовими надходженнями. ЗВП зовсім без надходжень (за «Усі ВП») — рядками його нульових членів. |
| **OFF** | Виводяться лише члени з ненульовими надходженнями. ЗВП зовсім без надходжень (за «Усі ВП») — одним зведеним нульовим рядком `Тип = ЗВП`. |

> Сумарний підсумок за рік **однаковий** за будь-якої комбінації Toggle 2/3 — змінюється лише деталізація, не сума (перевірено на реальних даних: 1 882 094,32 грн; нульові рядки нічого не додають).

### Комбінаторна таблиця (розгорнутий режим, Toggle 2 = ON)

| Усі ВП | Нульові члени | ЗВП: гроші на номер ЗВП | ЗВП: гроші на 1 члена | ЗВП без надходжень |
|---|---|---|---|---|
| ON | ON (default) | «ЗВП (пряме)» + усі члени (решта з 0) | усі члени (1 із сумою) | усі члени з 0 |
| ON | OFF | «ЗВП (пряме)» | 1 рядок члена із сумою | 1 рядок ЗВП із 0 |
| OFF | ON | «ЗВП (пряме)» + усі члени (решта з 0) | усі члени (1 із сумою) | пропущено |
| OFF | OFF | «ЗВП (пряме)» | 1 рядок члена із сумою | пропущено |

> Toggle 2 = OFF (згорнуто, default): кожне ЗВП — один рядок незалежно від Toggle 1/3.

|---|---|---|---|
| A | № АСВП | ВП.vpNum (для ЗВП — номер ЗВП) | 14 |
| B | Тип | `''` для звичайного, `ЗВП` для зведеного | 6 |
| C | № ВД | ВП.vd (для ЗВП — `—`) | 10 |
| D | Стан ВП | ВП.stanVP (для ЗВП — стани членів через ` / `) | 14 |
| E | Стан ВД | ВП.stanVD (для ЗВП — стани членів через ` / `) | 26 |
| F | Дата відкриття ВП | ВП.dateOpen (для ЗВП — порожньо) | 16 |
| G | Сума до стягнення, грн. | ВП.amount (для ЗВП — сума по членах) | 20 |
| H | Боржник | ВП.debtor (для ЗВП — спільний боржник) | 32 |
| I | Стягувач | ВП.creditor (для ЗВП — стягувачі через `; `) | 40 |
| J–U | Січень…Грудень {рік}, грн. | Сума надходжень за місяць | 16 |
| V | Разом {рік}, грн. | Сума за всі місяці | 18 |
| W | Склад ЗВП (№ АСВП членів) | Перелік № АСВП членів (тільки для рядків ЗВП) | 30 |

Один рядок = одне провадження. За замовчуванням зведене провадження (ЗВП) згортається в **один** рядок: його місячні суми = надходження на номер ЗВП **плюс** надходження на № АСВП кожного члена; окремі члени своїми рядками не виводяться (щоб уникнути подвійного рахунку). Тогл «Розгортати зведені (ЗВП)» перемикає на режим, де члени виводяться окремими рядками, а прямі надходження на ЗВП — рядком `Тип = ЗВП (пряме)`. Значення колонки **Тип**: порожньо (звичайне) / `ЗВП` / `член ЗВП` / `ЗВП (пряме)`. Див. розділ про ЗВП нижче.

## Критичні технічні рішення (lessons learned)

### 1. SheetJS обрізає порожні колонки зліва

**Проблема**: в файлі ВП колонка A порожня. SheetJS при `sheet_to_json({ header: 1 })` повертає масив без неї. Реальна колонка C (№ АСВП) потрапляє на індекс 1 замість 2.

**Вплив**: якщо шукати дані по фіксованому індексу — отримаєш неправильну колонку. Програма порівнюватиме номери ВД замість номерів АСВП і не знайде жодного збігу.

**Рішення**: колонки визначаються **виключно за назвами заголовків** через `findColIndex()`. Ніколи не використовуй жорсткі індекси для цих файлів.

**Це рішення критичне і не підлягає "оптимізації" або "спрощенню".**

### 2. Дві колонки сум у книзі депозитних сум

**Ситуація**: колонка I = "Залишок на початок місяця" (перенесено з попередніх періодів), колонка J = "Надійшло в поточному місяці".

**Правило**: використовуємо колонку J. Записи з J = 0 — пропускаємо (фактичного надходження не було в цьому місяці).

**Fallback**: якщо J не знайдена — використовуємо I (на випадок файлів іншого формату).

### 3. Пошук аркушу в книзі депозитних сум

**Проблема**: аркуш даних не завжди називається "Page2".

**Рішення**: спочатку шукаємо "Page2", потім — перший аркуш що містить текст "виконавчого провадження" в перших 10 рядках.

### 4. Під-заголовкові рядки

**Проблема**: після заголовків у Deposit бувають рядки з нумерацією колонок ("1", "2", "3"...) та текстові рядки ("Розшифровка залишку...").

**Рішення**: після знаходження заголовкового рядка скануємо наступні 5 рядків і шукаємо перший з 7+-значним числом у колонці VP.

### 5. Формат дат

**Проблема**: дати можуть прийти як Excel serial number (число) або як текст ("25.11.2020").

**Рішення**: `parseExcelDate` — якщо число → `XLSX.SSF.parse_date_code()`, якщо текст → повертається as-is.

### 6. Формат чисел

**Проблема**: суми можуть бути числами, рядками з комами ("1 234,56"), або null.

**Рішення**: `parseNum` — прибирає пробіли, заміняє кому на крапку, parseFloat, NaN → 0.

### 7. Зведені виконавчі провадження (ЗВП) — «сліпота» до надходжень

**Проблема**: іноді кілька ВП об'єднують у **зведене виконавче провадження** (ЗВП) — як правило, усі справи проти одного боржника. У реєстрі такі ВП мають заповнену колонку **«У складі ЗВП №»** (номер батьківського ЗВП). При цьому сам номер ЗВП **не має власного рядка** в реєстрі — є лише рядки окремих членів зі своїми № АСВП.

Кошти ж у книгу депозитних сум часто надходять **на номер самого ЗВП**, а не на номери членів. Оскільки зіставлення йде за № АСВП, а такого рядка в реєстрі немає, ці надходження раніше **повністю випадали зі звіту** (на реальних даних — 112 ЗВП, 553 958,52 грн, ≈11% усіх надходжень).

**Рішення**: кожне ЗВП згортається в **один** рядок (ідентифікований номером ЗВП, `Тип = "ЗВП"`). Його місячні суми = надходження на номер ЗВП **плюс** надходження на № АСВП кожного члена. Окремі члени своїми рядками не виводяться — тому подвійного рахунку немає. Спільний боржник, перелік стягувачів і № АСВП членів зберігаються в рядку (колонки H, I, W).

**Гарантії коректності** (перевірено на реальних файлах):
- номери ЗВП ніколи не перетинаються з реальними № АСВП → безпечно;
- відновлена сума точно дорівнює сумі надходжень на номери ЗВП;
- жоден член не виводиться окремо → grand total без подвійного рахунку.

## Для AI-агентів: правила модифікації

Цей розділ — для будь-якого AI (Claude, Gemini, GPT, Copilot), який буде модифікувати або підтримувати цей код.

### НІКОЛИ не роби

1. **НЕ заміняй `findColIndex()` на жорсткі індекси** — SheetJS обрізає порожні колонки, індекси будуть неправильними. Це вже спричинило баг, який було важко діагностувати (програма мовчки порівнювала неправильні колонки).

2. **НЕ видаляй фільтрацію `sum === 0`** в парсингу Deposit — нульові записи означають, що надходження не було в поточному місяці (залишок з минулого).

3. **НЕ міняй колонку суми з J на I** без явної вказівки користувача — I = залишок на початок місяця, J = надійшло в поточному.

4. **НЕ спрощуй пошук аркушу** в Deposit — не всі файли мають аркуш "Page2", потрібен fallback по тексту заголовка.

5. **НЕ додавай бекенд** без явної вимоги — клієнтська обробка — свідомий вибір (конфіденційність даних).

6. **НЕ використовуй `cellDates: true`** при читанні Excel — дати в цих файлах приходять як текст ("25.11.2020"), а `cellDates` може їх некоректно переінтерпретувати.

7. **НЕ прибирай згортання ЗВП** (колонка "У складі ЗВП №") — без нього надходження на номери зведених проваджень випадають зі звіту (≈11% коштів). Розгортання членів окремими рядками вже реалізоване як окремий тогл «Розгортати зведені (ЗВП)» (`toggleExpand`); обидва режими дають однаковий підсумок. Якщо чіпаєш Stage 4 — зберігай інваріант: сумарний `grandTotal` має бути однаковим у згорнутому й розгорнутому режимах (немає подвійного рахунку).

### Тестування після змін

Після будь-якої зміни в парсингу перевір на реальних файлах:

1. Файл ВП де колонка A порожня (стандартний експорт АСВП)
2. Файл Deposit з аркушем "Page2", merged cells, під-заголовковими рядками
3. Комбінації: ВП з надходженнями, ВП без надходжень, ВП якого немає в Deposit
4. Всі 4 комбінації тоглів

### Сигнатура `findColIndex`

```javascript
function findColIndex(headers, keywords) {
  // headers: string[] — масив заголовків одного рядка
  // keywords: string[] — фрагменти для пошуку (case-insensitive)
  // return: number — індекс першого збігу, або -1
  for (let i = 0; i < headers.length; i++) {
    const h = cleanStr(headers[i]).toLowerCase();
    if (keywords.some(kw => h.includes(kw.toLowerCase()))) return i;
  }
  return -1;
}
```

### Як додати нову колонку з файлу ВП

1. Знайди назву заголовка в реальному файлі (відкрий в Excel або подивись через SheetJS)
2. Додай ключове слово в `vCol`:
   ```javascript
   newField: findColIndex(vpH, ['фрагмент заголовка'])
   ```
3. Додай в extraction loop:
   ```javascript
   newField: vCol.newField >= 0 ? cleanStr(row[vCol.newField]) : ''
   ```
4. Додай в `outputRows.push(...)` — на потрібній позиції
5. Додай заголовок у масив `headers`
6. Додай ширину колонки в `outSheet['!cols']`

### Як додати нову колонку з Deposit

Аналогічно, але в `dCol` і в deposit map entry.
